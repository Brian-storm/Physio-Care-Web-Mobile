## 目標

驗證前端（Next.js）與後端（FastAPI）在 Docker Compose 環境下可正常啟動，且前端能成功透過 HTTP 呼叫後端 API（CORS、網路連通性）。建立一個簡單的端到端驗證測試。

## 情境包（Context Pack）

- 相關檔案：
  - `docker-compose.yml`
  - `frontend/src/app/page.tsx`
  - `backend/app/api/endpoints.py`
  - `backend/app/main.py`
- 既有模式：
  - 前端使用 `NEXT_PUBLIC_API_URL` 環境變數指向後端
  - 後端 CORS 白名單包含 `http://localhost:3000`（local dev）與 `http://localhost:3001`（Docker）
  - 後端提供 `/health` 端點與 `/api/v1/` CRUD endpoints
  - Frontend Docker container 透過 host network 存取 backend（`localhost:8001`）
- 假設：
  - Docker Compose environment 已正常啟動（T1-1-3 完成）
  - 無需真實攝影機或 MediaPipe 模型即可進行通訊驗證

  - 無

  - `docker-compose.yml`（若 CORS 或 port 需要調整）

## 需求

- 兩個 container 皆正常啟動且無 crash
- 從 frontend container 可 `curl http://backend:8000/health`（Docker internal network）
- 從瀏覽器（host）可透過 `http://localhost:8001/health` 存取後端
- 從瀏覽器（host）可透過 `http://localhost:3001` 存取前端頁面
- 前端頁面可透過 `fetch('http://localhost:8001/health')` 取得後端回應（CORS 驗證）
- 建立一個自動化驗證腳本，檢查以上所有條件

## 驗收標準

- `docker compose up -d` 後 10 秒內兩個 service 皆 healthy
- `docker compose exec frontend wget -qO- http://backend:8000/health` 回傳 200
- 瀏覽器開啟 `http://localhost:3001` 可看到頁面
- 瀏覽器 Console 無 CORS error
- 驗證腳本執行後 exit code 0

## 實作備註

- 在 `backend/app/core/config.py` 的 `cors_origins` 中加入 `http://localhost:3001`（若尚未加入）
- 驗證腳本可寫於 `scripts/verify-communication.sh`（或 `.ps1` for Windows）
- 簡單的驗證方式：前端 page.tsx 的 `useEffect` 中呼叫 `/health` 並顯示連線狀態
