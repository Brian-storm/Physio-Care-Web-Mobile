## 目標

將 `useSession` hook 收集的 session summary 透過 `POST /api/v1/sessions` endpoint 儲存到後端資料庫。實作一個 `saveSession` API 服務函式，並在 session 結束時（使用者點擊「Save & Close」）自動觸發儲存。

## 情境包（Context Pack）

- 相關檔案：`frontend/src/hooks/useSession.ts`（T3-3-1，提供 SessionSummary）、`frontend/src/components/SessionSummary.tsx`（T3-3-2，觸發 onSave）、`backend/app/api/endpoints.py:63-70`（現有 POST /sessions endpoint）、`backend/app/schemas/schemas.py:56-67`（SessionCreate schema）、`backend/app/models/models.py:41-55`（SessionRecord model）
- 既有模式：後端已實作完整的 `POST /api/v1/sessions` endpoint，接受 `patient_id`、`exercise_id`、`reps_completed`、`sets_completed`、`avg_form_score`、`max_danger_score`、`pain_score`、`flagged`、`duration_seconds` 欄位。
- 假設：前端在 session summary 儲存時尚未有真實的 `patient_id` 與 `exercise_id`（這些來自 patient/therapist 頁面的 context）。初期先使用 placeholder 值（如 `"demo-patient"`、`"demo-exercise"`），或將這些 ID 透過 props 傳入。
- 未知事項：使用者是否需要在儲存前輸入 pain score（目前 SessionCreate schema 有 pain_score 欄位）。初期預設 pain_score = 0，未來可在 SessionSummary 中新增 pain score input。
- 允許變更的檔案：`frontend/src/services/api.ts`（新檔案，API 服務層）、`frontend/src/app/page.tsx`（串接 saveSession 邏輯）、`frontend/src/components/SessionSummary.tsx`（傳遞 patient_id/exercise_id props）
- 不得觸碰：`backend/app/`（endpoint 已就緒，無需修改）、`frontend/src/hooks/useSession.ts`（hook 不負責 API 呼叫）

## 需求

- 建立 `frontend/src/services/api.ts` 檔案，包含：
  ```ts
  export async function saveSession(data: SessionCreatePayload): Promise<SessionResponse>
  ```
- `SessionCreatePayload` 型別定義對應後端 `SessionCreate` schema：
  ```ts
  interface SessionCreatePayload {
    patient_id: string;
    exercise_id: string;
    reps_completed: number;
    sets_completed: number;
    avg_form_score: number;
    max_danger_score: number;
    pain_score: number;
    flagged: boolean;
    duration_seconds: number;
  }
  ```
- API URL 從環境變數或預設值取得（`process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8000'`）。
- 使用 `POST /api/v1/sessions`，請求 header 包含 `Content-Type: application/json`。
- 錯誤處理：網路錯誤或 non-2xx 回應時 throw 包含狀態碼與錯誤訊息的 Error。
- 在 page.tsx（或上層元件）中：
  - 當 SessionSummary 的 onSave 被觸發時，將 `useSession().summary` 轉換為 `SessionCreatePayload` 並呼叫 `saveSession`。
  - 匯入 `patient_id` 與 `exercise_id`（初期使用 props 或 hardcoded demo 值）。
  - 儲存成功後顯示成功提示（或將 status 設為 idle 讓使用者重新開始）。
  - 儲存失敗時顯示錯誤訊息（不關閉 summary modal，允許重試）。
- SessionSummary 元件新增 `patientId` 與 `exerciseId` props（字串）。
- 檔案 header 註解（api.ts）：`/* PhysioCare — REST API client layer for backend endpoints */`

## 驗收標準

- `saveSession` 正確發送 POST request 到後端。
- 請求 body 符合 SessionCreate schema 格式。
- 成功回應後回傳 SessionResponse。
- 網路錯誤或 4xx/5xx 時 throw 可讀的 Error。
- 點擊 SessionSummary 的「Save & Close」按鈕觸發儲存流程。
- 儲存成功後 session 狀態重置為 idle。
- 儲存失敗時顯示錯誤並且不重置狀態（允許重試）。
- 無 TypeScript 錯誤，無 lint 警告。

## 實作備註

- 使用原生 `fetch`，不額外引入 axios 等 HTTP 客戶端。
- SessionSummary 的 onSave callback 改為 async，在儲存期間顯示 loading 狀態。
- 後端的 POST /sessions endpoint 不需要身分驗證（demo phase，未來會補上 auth middleware）。
- demo 階段的 patient_id 與 exercise_id 可從 page.tsx 的 query params 或 props 傳入。
