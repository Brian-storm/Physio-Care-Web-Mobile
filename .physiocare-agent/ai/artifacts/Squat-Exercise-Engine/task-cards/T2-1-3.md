## 目標

提供一個 React hook 封裝 MediaPipe `PoseLandmarker` 的初始化與逐幀偵測，回傳 `init()` 與 `detect(video, timestamp)` API 以及初始化的 loading 狀態。

## 情境包（Context Pack）

- 相關檔案：
  - `frontend/src/hooks/usePose.ts` — 已實作完整 hook
  - `frontend/src/services/poseService.ts` — 底層 `initPoseDetector()` / `detectPose()`
  - `frontend/src/types/pose.ts` — `PoseLandmarks` 型別
  - `frontend/src/hooks/useCamera.ts` — camera 端，提供 videoRef
- 既有模式：
  - `usePose` 使用 `useRef<boolean>` 作為初始化 guard（idempotent）
  - `init()` 為 async callback，設定 `isInitializing` / `isInitialized` 狀態
  - `detect()` 僅在已初始化時才呼叫底層服務
  - 失敗時 throw Error 給上層 component 處理
- 假設：
  - `init()` 在 camera `isReady` 之後才被呼叫
  - `detect()` 在 `requestAnimationFrame` 或 `OffscreenCanvas` 的每一幀呼叫
  - `timestamp` 使用 `performance.now()`
- 未知事項：
  - `detect()` 在 30fps 下的呼叫頻率對主執行緒的影響
  - 多次 `init()` 的 race condition 處理（目前用 ref guard 防止）
- 允許變更的檔案：
  - `frontend/src/hooks/usePose.ts` (微調)
- 不得觸碰：
  - `frontend/src/types/pose.ts`
  - `frontend/src/services/poseService.ts` (除非需共用修正)

## 需求

- `init()` 為 idempotent：第一次呼叫時初始化 `PoseLandmarker`，後續直接 return。
- `isInitializing` 在初始化中為 `true`。
- `isInitialized` 在初始化成功後為 `true`。
- `detect(video, timestamp)` 回傳 `PoseLandmarks | null`。
- 初始化失敗必須 throw Error 讓消費端（component）以 error boundary 或 try/catch 處理。
- 回傳值型別完全符合 `@/types/pose` 的 `PoseLandmarks` 介面。

## 驗收標準

- 呼叫 `init()` 後 `isInitialized` 最終為 `true`。
- 重複呼叫 `init()` 只初始化一次。
- `detect()` 在未初始化時回傳 `null`。
- `detect()` 在有人的 frame 回傳非 null 的 `PoseLandmarks`（內含 33 個 landmarks）。
- 型別正確，`npm run build` 無 error。
