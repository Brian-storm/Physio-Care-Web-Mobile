## 目標

在 `SquatEngine` 中實作 running score 機制，以加權移動平均（weighted moving average）平滑化逐幀的 formScore，減少單幀雜訊造成的分數抖動，提供更穩定的使用者體驗。

- 相關檔案：
  - `frontend/src/utils/exerciseEngine.ts` — `SquatEngine.update()` 目前回傳「instantaneous」formScore（僅基於當前幀）
  - `frontend/src/types/pose.ts` — `ExerciseState` 的 `formScore` 與 `FormFeedback.score`
  - `frontend/src/utils/__tests__/exerciseEngine.test.ts` — 需更新測試案例

  - 無平滑機制，分數可能因單幀雜訊劇烈波動
- 假設：
  - N 幀視窗 = 30（約 1 秒 @30fps），可配置
  - 加權方式：指數加權（exponential weighted）或簡單移動平均（SMA）

  - 最佳 N 值需實測決定（太少則不平滑，太多則反應遲鈍）

## 需求

- `SquatEngine` 維護一個 running score（0-100），為最近 N 幀 formScore 的加權平均。
- 預設 N = 30（~1 秒視窗），可在建構子配置。
- 加權方式：最近幀權重最高，最舊幀權重最低（指數衰減或線性遞減）。
- `update()` 回傳的 `ExerciseState.formScore` 改為 running score（或新增 `runningScore` 欄位）。
- 實作 `getRunningScore(): number` 方法查詢當前 running score。
- `reset()` 應清空 running score 歷史。

## 驗收標準

- 單幀突然 drop（如膝蓋外翻 1 幀）不會讓 running score 劇烈下降（平滑效果）。
- 持續 bad form 5 幀後 running score 顯著下降（反映真實趨勢）。
- `reset()` 後 running score 回到 100（初始值）。
- 可配置 N 值（建構子參數 `windowSize`）。
- 現有測試（T2-3-4）仍全部通過（或更新測試以匹配新行為）。

## 實作備註

- 建議使用指數加權移動平均（EWMA）：`runningScore = α * instantScore + (1-α) * previousRunningScore`，α = 2/(N+1)。
- EWMA 只需儲存前一個 running score，不需完整 N 幀陣列，記憶體效率高。
- 初期幀數不足 N 時，使用可用幀數計算（warm-up 階段）。
