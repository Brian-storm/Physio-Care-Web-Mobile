## 目標

驗證 `SquatEngine` 的整體輸出格式，確保 `update()` 與 `evaluateFrame()` 回傳的資料結構完整、型別正確、內容合理，且在前端 UI 消費時不需要額外轉換。

- 相關檔案：
  - `frontend/src/utils/exerciseEngine.ts` — `SquatEngine` 最終版本
  - `frontend/src/types/pose.ts` — `ExerciseState`、`FormFeedback`、`JointAngle`、`ExercisePhase`
  - `frontend/src/hooks/usePose.ts` — rAF 循環消費端
  - `frontend/src/app/page.tsx` 或測試頁面 — UI 消費端

  - `SquatEngine.update()` 回傳 `ExerciseState`
  - `SquatEngine.evaluateFrame()` 回傳 `FormFeedback`（若已實作）

- 假設：
  - Running score（T2-4-1）已完成
  - Cue prioritization（T2-4-2）已完成

  - 是否需要將 `ExerciseState` 或 `FormFeedback` 序列化為 JSON（儲存或傳送）

- 允許變更的檔案：
  - `frontend/src/utils/exerciseEngine.ts` (微調輸出格式)
  - `frontend/src/types/pose.ts` (微調型別欄位)

- 不得觸碰：
  - `frontend/src/hooks/`
  - `frontend/src/services/`

## 需求

- `ExerciseState` 的所有數值欄位在合理範圍內（formScore 0-100, dangerScore 0-100, repCount ≥ 0）。
- `FormFeedback.score` 與 `ExerciseState.formScore` 一致（running score）。
- `FormFeedback.cues` 為排序後的非空字串陣列，最多 3 條。
- `JointAngle[]` 中每筆的 `name`、`value`、`target`、`deviation`、`status` 均有值且合理。
- `ExercisePhase` 僅為 `idle | descending | bottom | ascending | completed` 之一。
- 輸出格式可直接被 React component 消費（props 傳遞無需轉換）。
- 所有時間戳使用 `number`（`Date.now()`）格式。

## 驗收標準

- 連續 60 幀輸出資料全數通過格式驗證（range check、type check）。
- `score` 始終在 [0, 100]。
- `phase` 始終為合法的 `ExercisePhase` 值。
- `cues` 陣列長度 ≤ 3。
- 每筆 `JointAngle.deviation` = `|value - target|`。
- 每筆 `JointAngle.status` 為 `under | target | over` 之一。
- `npm run build` 無 type error。

## 實作備註
