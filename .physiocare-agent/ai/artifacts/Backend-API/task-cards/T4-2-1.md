## Objective

Define an `Exercise` SQLModel in `backend/app/models/models.py` that represents an exercise with a `form_rules` JSON field for storing configurable form-checking parameters.

## Context Pack

- Relevant files: `backend/app/models/models.py` (contains `PrescribedExercise` model — similar but different), `backend/app/schemas/schemas.py`
- Existing patterns: `PrescribedExercise` already exists with safety fields (safety_max_knee_valgus, safety_min_hip_angle, etc.). A new `Exercise` model is needed per spec — this is a distinct entity, not a rename.
- Assumptions: Exercise is a standalone catalog/ reference exercise (not prescribed to a patient). PrescribedExercise remains for patient-specific prescriptions.
- Unknowns: Relationship between Exercise and PrescribedExercise (should PrescribedExercise have an exercise_id foreign key?)
- Allowed to modify: `backend/app/models/models.py`, `backend/app/schemas/schemas.py`
- Do not touch: `backend/app/api/endpoints.py` (unless adding new endpoints per T4-2-2)

## Requirements

1. Class name `Exercise`, extends `SQLModel, table=True`
2. `id: str` — primary key, default uuid4
3. `name: str`
4. `description: str = ""`
5. `form_rules: str = "{}"` — JSON string for configurable form-checking rules (e.g., target angles, rep thresholds)
6. `created_at: datetime` — default `datetime.utcnow`

## Acceptance Criteria

- `from app.models.models import Exercise` succeeds
- Table `exercise` is created in SQLite
- Can insert Exercise(name="Squat", form_rules='{"min_hip_angle": 60}') successfully
- Can read back and parse form_rules as JSON

## Implementation Notes

- `form_rules` is stored as a JSON string; use `json.loads()` in service layer to parse
- Alternatively, use `type: dict | None = None` with `sa_column=Column(JSON)` if SQLModel supports it. Check SQLModel docs for JSON column support.
