## Objective

Define a `Feedback` SQLModel in `backend/app/models/models.py` for storing per-frame feedback data during an exercise session, including angle measurements, verbal cues, and frame-level scores.

## Context Pack

- Relevant files: `backend/app/models/models.py` (contains `FlaggedClip` model — different purpose), `backend/app/schemas/schemas.py`
- Existing patterns: `FlaggedClip` stores session_id + patient_id for flagged clips. Feedback is a new concept — frame-level telemetry for every session.
- Assumptions: Feedback records are per-frame, so many Feedback rows per Session. No existing model covers this.
- Unknowns: Exact schema for `angle_data` and `cues` — should they be JSON strings? Dicts?
- Allowed to modify: `backend/app/models/models.py`, `backend/app/schemas/schemas.py`
- Do not touch: `backend/app/api/endpoints.py` (until T4-3-4)

## Requirements

1. Class name `Feedback`, extends `SQLModel, table=True`
2. `id: str` — primary key, default uuid4
3. `session_id: str` — foreign key to `session.id`
4. `timestamp: float` — seconds into the session when this frame was captured
5. `angle_data: str = "{}"` — JSON string storing joint angles for this frame (e.g., `{"hip": 72.3, "knee": 45.1}`)
6. `cues: str = "[]"` — JSON string array of verbal cues triggered (e.g., `["straighten back", "bend knees more"]`)
7. `frame_score: float` — score for this individual frame (0.0 to 1.0)

## Acceptance Criteria

- `from app.models.models import Feedback` succeeds
- Table `feedback` created in SQLite
- Can insert a Feedback record with valid session_id
- Can read back and parse `angle_data` and `cues` as JSON

## Implementation Notes

- `angle_data` and `cues` stored as JSON strings for simplicity; parse with `json.loads()` on read
- Consider using SQLModel's `JSON` type if available for native JSON column support
- Feedback is expected to be write-heavy (many frames per session) — no indexing needed initially
