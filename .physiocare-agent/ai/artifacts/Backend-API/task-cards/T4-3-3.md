## Objective

Add two session endpoints in `backend/app/api/endpoints.py`: create a session (POST) and list sessions (GET).

## Requirements

1. `POST /sessions` — create a session, return session data with 201 status
   - Accept: `patient_id`, `exercise_id`, `score`, `duration`
   - Return: full session with `id`, `started_at`, etc.
2. `GET /sessions` — list all sessions (or list by patient if patient_id query param)
   - Return array of sessions, ordered by `started_at` descending

## Acceptance Criteria

- `POST /sessions` with valid patient_id and exercise_id returns 201
- `GET /sessions` returns array (empty if none)
- Invalid patient_id or exercise_id returns 404
- `GET /sessions?patient_id={id}` filters by patient

## Implementation Notes

- If using existing `SessionRecord`: may need to rename endpoints from `/patients/{patient_id}/sessions` to top-level `/sessions`
- If adding new `Session` model: create `SessionCreate` and `SessionResponse` schemas
- Add foreign key validation in POST handler (verify patient and exercise exist)
